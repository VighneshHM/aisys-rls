AISYS RFID Library · 1 of 12

Add RFID to an existing library system without touching its records

The problem

  • A library already runs an ILMS and has a spreadsheet of holdings (about 20,000 rows).
  • It wants RFID tagging, self-service circulation, shelf inventory and a security gate, added around the ILMS.
  • Existing records must stay safe: nothing may be edited or lost.

The scope

  • An add-on that joins the ILMS through a connector interface.
  • Ten acceptance scenarios (AC01 to AC10) and deliverables D0 to D9.
  • Every device and outside service is mocked behind an interface; all data is synthetic.
  • No real reader, gate, camera, printer, mail service or ILMS was connected.

What is mocked, and why: no real hardware or vendor ILMS was available, and the exercise rule is to prove the interfaces, not any vendor. The SIP2 client is tested against a simulator only.

Speaker notes

Open with the scope: this is an add-on, not an ILMS replacement. Say clearly that everything outside the add-on is a mock, so nothing later sounds like a claim about real hardware. The data is synthetic throughout (docs/index.md, docs/assumptions.md).

Data safety (NFR01) · 4 of 12

An import can never corrupt the library

Stageevery row kept verbatim
→
Validatedry run, library untouched
→
Back upverified before commit
→
Commitinsert-only, one transaction
→
Reconcilecounts and fingerprint
→
Roll backby batch, if needed
  • Staging first; duplicates are skipped and reported, never merged.
  • Backup before every change: before each import and each restore, verified by an integrity check and a checksum.
  • Per-table proof: row count and SHA-256 of every table; Compare lists each table as identical or different.
  • Restore with a safety copy: typed RESTORE, a pre-restore copy is saved, every table is re-proved, and a mismatch puts the safety copy back.
Speaker notes

docs/migration.md and docs/backup-restore.md. Mention maintenance mode: while a restore runs, everyone else gets a clean 503 for a few seconds, so no change is lost or half applied (defect D-012). Committed examples of both reports are in docs/samples/.

Integration · 5 of 12

Retries that cannot double-count, devices behind Protocols

The ILMS connector

  • Check-out, renew and check-in go through one CirculationConnector.
  • Failed calls are retried; every retry carries the same transaction id, so a repeat is not applied twice.
  • driver = "sip2" speaks SIP2 2.00 over TCP ([ilms] endpoint, port; password only from AISYS_ILMS_PASSWORD); a lost answer is verified with the ILMS before any repeat. Tested against a simulator only; mock is the default.

Devices

  • Staff reader, handheld, gate, camera and card printer are each a Protocol.
  • Selected by driver in [[devices]]; mock is built in.
  • The gate alarms from the security bit, so it works while the ILMS is down.

Notifications

  • Queued first, then delivered, so a mail outage never blocks the desk.
  • Each message is claimed atomically before sending: delivered exactly once.
  • Attempts and back-off are settings.
Speaker notes

docs/circulation.md, docs/sip2.md, docs/rfid.md, docs/gate.md, docs/reminders.md. A real device or provider needs a driver class; the address of a real device is not a [[devices]] key today and belongs to that driver (docs/site-addressing.md). Defect D-029 (two dispatchers sent the same message twice) is on slide 10.

Security (NFR02) · 6 of 12

Least privilege, signed packages, nothing secret in logs

Access

  • Four roles (administrator, librarian, desk clerk, auditor); every endpoint checks a permission.
  • Staff card signs in; a patron card never does.
  • Lock-out after repeated failures; last administrator protected.
  • Settings changes need admin.config and are audited with old and new values.

Protection

  • Ed25519-signed update packages; tampered, foreign-signed and older packages are refused.
  • TLS directly or behind a proxy; production cookies are Secure.
  • Card numbers masked in the audit log; audit lines cannot be edited or deleted.

Checks

  • Hostile-input tests: SQL and wildcard text, formulas in CSV, HTML, path traversal, giant numbers.
  • Dependency audit (pip-audit) and security lint rules on every pull request.
  • Not done: penetration test, multi-factor sign-in.
Speaker notes

docs/security-checks.md lists each check and how to re-run it. The dependency audit found 7 known vulnerabilities in cryptography 48.0.0 during the work; fixed by pinning 50.0.2 (D-021). Be honest about what is left: a content-security-policy, a penetration test and multi-factor sign-in are in docs/remaining-work.md.

  • Recover after a crash mid-update with manage.py recover.

Search and shelves · 8 of 12

Search while typing; see where the book is

Full-text index

  • SQLite FTS5, ranked, kept current by database triggers (real-time indexing).
  • Substring matching only when the index finds nothing.
  • Measured at 20,000 items: about 117 to 121 ms median, under 140 ms at the 95th percentile (target 300 ms).

Public catalogue

  • /opac without sign-in: titles, shelves and availability only.
  • Rate-limited to 60 searches a minute per address; can be switched off in Settings.

Virtual bookshelf

  • A row of spines in call-number order, the wanted book outlined.
  • After an inventory sweep, books out of order are outlined to move.
  • First 300 books of the biggest location (4,704): 247 ms median.
Speaker notes

docs/performance-results.md has every figure. The first measured search time was 1.3 to 3.3 s; slide 10 explains the fix (D-028). Demo: type a few letters in the catalogue, open /opac signed out, press Show the shelf.

Known limits · 11 of 12

A tested prototype, not a finished product

Not built, by decision

  • NCIP 2.0 is not built; SIP2 is built (a subset) but tested only against a simulator, not certified or tried on a vendor ILMS.
  • No real reader, handheld, gate, camera, printer, mail or SMS drivers.
  • Not a full ILMS: no budgets, holds or inter-library loan.

Needs a production site

  • A site acceptance test with library staff (blank form: docs/uat-signoff.md).
  • A soak test on a server-class machine.
  • TLS proxy and service wrapper set up and tested; a real Windows Server 2022 install.

Limits to know

  • SQLite only: one writer at a time; PostgreSQL is a future option.
  • No penetration test; no multi-factor sign-in.
  • Backups stay on the machine unless copied off; no automatic retention.

The full list with next steps is docs/remaining-work.md.

Speaker notes

Say plainly that the UAT was run by the development team and the devices are simulated, so this is not acceptance by the library. The same goes for the ILMS: the SIP2 client has only met the simulator (docs/sip2.md), and SIP2 itself needs a tunnel because it is unencrypted. The production backlog in docs/remaining-work.md is the next piece of work.
